Я бы "чннил" это через добавлене метода make_many_sounds(int) в класс Cat, или через добавление в сигнатуру make_sound параметра number_of_sounds со значением по умолчанию 1. (Хоть это и ведет к другим проблемам, как было описано в СИ)

- 3) Сложно однозначно сказать (без хорошего понимания Java), но что показалось подозрительным исходя из того, что обсуждалоь в теоретической части:
    - 2 версии jackson-databind в зависимостях
    - Main предполагает, что результат десериализации это просто мапа, из которой можно вытащить "name". Т.е. если завтра JSON станет сложнее, то весь код, который "знает", что это HashMap, станет хрупким
    - try/catch в парсинге - если парсинг упал (result=null), вторая часть кода Main (pretty print) полагается на то, что там валидные данные
