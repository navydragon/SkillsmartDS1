# Параллельная обработка большого массива данных

## Описание

Этот проект демонстрирует **существенно упрощённый** вариант параллельной обработки большого массива данных. Основное упрощение заключается в замене низкоуровневых механизмов синхронизации (`synchronized` в Java / `Lock` в Python) на высокоуровневый API `ThreadPoolExecutor`, который автоматически управляет потоками и позволяет избежать явной синхронизации.

## Ключевое упрощение

### Исходный подход (Java с synchronized)

```java
private static volatile int sum = 0;

// В каждом потоке:
synchronized (ComplexMultiThreadProcessing.class) {
    sum += localSum;  // Нужна синхронизация для общей переменной
}
```

**Проблемы:**
- Требуется явная синхронизация через `synchronized`/`Lock`
- Общая переменная `sum` нуждается в защите от состояния гонки
- Необходимо управлять блокировками вручную
- Риск забыть освободить блокировку или получить deadlock

### Упрощённый подход (Python с ThreadPoolExecutor)

```python
def process_chunk(data, start, end, thread_id):
    local_sum = 0
    for i in range(start, end):
        local_sum += data[i]
    return local_sum  # Возвращаем результат, а не обновляем общую переменную

# В главном потоке:
with ThreadPoolExecutor(max_workers=THREADS) as executor:
    futures = [executor.submit(process_chunk, ...) for ...]
    sum_total = sum(future.result() for future in futures)  # Без синхронизации!
```

**Преимущества:**
-  **Нет явной синхронизации** - каждый поток возвращает свой результат
-  **Нет общей переменной** - результаты собираются в главном потоке
-  **Проще код** - не нужно управлять блокировками
-  **Меньше ошибок** - нет риска забыть освободить блокировку
-  **Автоматическое управление потоками** - `ThreadPoolExecutor` сам управляет жизненным циклом


В упрощённом подходе:
1. **Каждый поток работает независимо** - обрабатывает свою часть массива
2. **Каждый поток возвращает свой результат** - не обновляет общую переменную
3. **Главный поток собирает результаты** - он один, поэтому гонки данных нет

В исходном подходе:
- Несколько потоков **одновременно обновляли** общую переменную `sum`
- Требовалась синхронизация для защиты от состояния гонки


- Каждый поток обрабатывает свою непересекающуюся часть массива
- Каждый поток возвращает корректную локальную сумму
- Главный поток собирает результаты последовательно (без гонки данных)
- Результат всегда совпадает с однопоточным вычислением
