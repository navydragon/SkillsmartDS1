# Функциональный подход к калькулятору оценок

## Обзор

Этот документ демонстрирует переписывание класса `GradeCalculator` в функциональном стиле, следуя принципам функционального программирования (ФП).

## Основные принципы функционального программирования

### 1. Иммутабельность (Immutability)

**В императивном стиле:**
```python
class GradeCalculator:
    def calculateAverage(self, grades: List[float]) -> float:
        # Метод изменяет состояние или работает с мутабельными данными
        self._validate(grades)  # Может изменять внутреннее состояние
        return sum(grades) / len(grades)
```

**В функциональном стиле:**
```python
@dataclass(frozen=True)
class GradeList:
    grades: Tuple[float, ...]  # Иммутабельный кортеж
    
    def add_grade(self, grade: float) -> 'GradeList':
        # Создает НОВЫЙ объект вместо изменения текущего
        return GradeList(self.grades + (grade,))
```

**Ключевые отличия:**
- Класс помечен как `frozen=True` - нельзя изменять после создания
- Используется `Tuple` вместо `List` - кортежи иммутабельны
- Методы возвращают новые объекты, а не изменяют существующие

### 2. Чистые функции (Pure Functions)

**Чистая функция** - это функция, которая:
- Не имеет побочных эффектов (не изменяет глобальное состояние)
- Для одних и тех же входных данных всегда возвращает одинаковый результат
- Не зависит от внешнего состояния


## Сравнение подходов

### Императивный стиль (оригинальный)

```python
calculator = GradeCalculator()
average = calculator.calculateAverage([5.0, 4.5, 3.0])
# Объект calculator может иметь внутреннее состояние
# Методы могут изменять это состояние
```

### Функциональный стиль

```python
# Вариант 1: Использование иммутабельного объекта
grade_list = GradeList((5.0, 4.5, 3.0))
average = grade_list.calculate_average()

# Добавление оценки создает новый объект
new_grade_list = grade_list.add_grade(4.0)
# grade_list остается неизменным!

# Вариант 2: Использование чистой функции
average = calculate_average([5.0, 4.5, 3.0])
```
