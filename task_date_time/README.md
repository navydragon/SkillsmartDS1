# Работа с датой и временем

## Описание

Этот проект демонстрирует, как код, выглядящий просто, может оказаться реально сложным. Работа с датой и временем — одна из наиболее болезненных тем в разработке (наряду с кодировкой). Здесь множество подводных камней: часовые пояса, переход на летнее/зимнее время, форматы дат/времени и т.д.

## Исходная проблема

Рассмотрим простой Java код для парсинга даты:

```java
import java.text.ParseException;
import java.text.SimpleDateFormat;
import java.util.Date;

public class DateExample {
    public static void main(String[] args) {
        String dateString = "2024-05-13 14:30:00";
        SimpleDateFormat format = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
        try {
            Date date = format.parse(dateString);
            System.out.println("Date: " + date);
        } catch (ParseException e) {
            e.printStackTrace();
        }
    }
}
```

На первый взгляд код выглядит простым и правильным, но на практике он содержит множество проблем.

## Недостатки исходного кода

### 1. Отсутствие явного указания часового пояса
- Используется системный часовой пояс по умолчанию
- Непонятно, в каком часовом поясе интерпретируется дата
- При работе с данными из разных источников возникает неоднозначность

### 2. SimpleDateFormat не потокобезопасен
- В многопоточных приложениях может привести к гонкам данных
- Требует синхронизации или создания нового экземпляра для каждого потока

### 3. Нет валидации входных данных
- Некорректные строки вызывают исключения
- Пустые строки не обрабатываются
- Нет проверки на разумность значений (например, 13-й месяц)


### 5. Нет обработки edge cases
- Некорректный формат приводит к исключению
- Нет обработки различных форматов дат
- Нет fallback механизмов

### 6. Нет явного указания локали
- Форматирование зависит от системных настроек
- Разные локали могут давать разные результаты

### 7. Проблемы с переходом на летнее/зимнее время
- Не учитываются DST переходы
- Могут возникнуть неоднозначности (одно время в двух часовых поясах)
- Пропуск или повторение времени при переходах

## Улучшенное решение

### Основные принципы

1. **Явное указание часового пояса**
   - Всегда указывайте часовой пояс при создании datetime
   - Используйте UTC для внутреннего хранения
   - Конвертируйте в локальный часовой пояс только для отображения

2. **Валидация входных данных**
   - Проверка на пустые строки
   - Проверка формата перед парсингом
   - Обработка различных форматов

3. **Правильная обработка ошибок**
   - Специфичные исключения (DateParseError)
   - Информативные сообщения об ошибках
   - Graceful degradation

4. **Поддержка различных форматов**
   - Множественные форматы дат
   - Автоматическое определение формата
   - Расширяемость

5. **Работа с часовыми поясами**
   - Конвертация между часовыми поясами
   - Учет переходов на летнее/зимнее время
   - Сохранение в UTC для внутреннего использования

### Примеры использования

#### Парсинг с явным указанием UTC

```python
from datetime import timezone
from improved_date_example import DateParser

parser = DateParser(default_timezone=timezone.utc)
date = parser.parse_utc("2024-05-13 14:30:00")
print(date)  # 2024-05-13 14:30:00+00:00
```

#### Парсинг с указанием локального часового пояса

```python
# MSK (UTC+3)
date_msk = parser.parse_local("2024-05-13 14:30:00", timezone_offset_hours=3)
print(date_msk)  # 2024-05-13 14:30:00+03:00
```

#### Конвертация между часовыми поясами

```python
date_utc = parser.to_utc(date_msk)
print(date_utc)  # 2024-05-13 11:30:00+00:00
```

#### Форматирование для хранения в БД

```python
storage_format = parser.format_for_storage(date_msk)
print(storage_format)  # 2024-05-13T11:30:00+00:00 (всегда UTC, ISO формат)
```
